
# DAST: процес тестування

1. Запустити застосунок локально (docker-compose або `flask run`).
2. Запустити ZAP baseline scan: `make zap` або CI воркфлоу.
3. Зберегти HTML-звіт у `reports/zap/`.
4. Внести підсумки: знайдені проблеми, рівні критичності, план виправлень.

## Підсумки сканування (OWASP ZAP)

**Знайдені проблеми та рівні критичності:**
1. **SQL впровадження** (High) — знайдено в параметрах пошуку, дозволяє маніпуляції з БД.
2. **Міжсайтовий сценарій / XSS** (High) — відсутнє екранування вводу користувача.
3. **Відсутність токенів Anti-CSRF** (Medium) — форми не захищені від підробки запитів.
4. **Відсутні заголовки безпеки** (Low) — відсутні X-Frame-Options та CSP, що дозволяє клікджекінг.

**План виправлень:**
- Використати параметризовані запити для бази даних (виправлення SQLi).
- Впровадити обов'язкове екранування HTML-сутностей при виводі даних (виправлення XSS).
- Інтегрувати механізм генерації та перевірки CSRF-токенів.
- Налаштувати серверну видачу HTTP-заголовків безпеки.

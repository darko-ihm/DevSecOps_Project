# Підсумковий аудит безпеки та рекомендації

## 1. Стан виконання вимог
Початкові вимоги щодо інтеграції безпеки в SDLC (DevSecOps) виконано. Налаштовано конвеєр CI/CD із SAST-сканерами (Semgrep, Bandit), розгорнуто тестове середовище (Docker) та проведено DAST-тестування (OWASP ZAP). Виявлені вразливості (SQLi, XSS) задокументовано, очікується їх виправлення розробниками.

## 2. Ролі учасників у процесі DevSecOps
- **Розробник (Dev):** Відповідає за написання безпечного коду, аналіз звітів SAST у GitHub Actions та виправлення знайдених вразливостей.
- **Інженер з безпеки (Sec):** Формує модель загроз, налаштовує правила сканування (Semgrep), проводить ручний аудит та валідацію результатів DAST (ZAP).
- **Інженер інфраструктури/Ops:** Налаштовує CI/CD конвеєри, керує Docker-контейнерами та забезпечує стабільність середовища тестування.

## 3. Рекомендації щодо вдосконалення
З огляду на обрану модель DevSecOps, рекомендується:
1. Впровадити автоматичне блокування злиття коду (Merge blocking), якщо SAST знаходить вразливості рівня High/Critical.
2. Інтегрувати IAST (інтерактивне тестування) для більш точного аналізу під час роботи додатка.
3. Регулярно оновлювати бази правил OWASP ZAP та Semgrep для протидії новим загрозам.

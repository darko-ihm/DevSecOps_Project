# Модель загроз (STRIDE)

## Контекст
Публічний Flask вебдодаток, БД SQLite, мінімальна аутентифікація.

## STRIDE-матриця
- **S**poofing: підробка облікових даних, сесійні cookie без прапорців безпеки.
- **T**ampering: SQL-ін'єкції (SQLi) для модифікації даних у БД.
- **R**epudiation: недостатній аудит подій логіну.
- **I**nformation Disclosure: XSS для крадіжки cookie, витік конфігурацій/секретів.
- **D**enial of Service: зловмисні автоматизовані запити до ендпоінту `/search`.
- **E**levation of Privilege: слабкі перевірки доступу до адмін-функцій.

## 3 сценарії атак
1) **SQL Injection (SQLi) у `/search`**
   - **Вектор:** параметр `q` передається прямо в SQL-запит.
   - **Виявлення:** SAST (Semgrep/Bandit), DAST (ZAP SQLi), мануальні тести.
   - **Пом'якшення:** використання параметризованих запитів або ORM.

2) **Reflected XSS у `/echo`**
   - **Вектор:** параметр `msg` повертається як HTML без екранування.
   - **Виявлення:** ZAP, браузерні індикатори (XSS Auditor).
   - **Пом'якшення:** HTML-екранування (escaping), налаштування CSP, валідатори.

3) **Слабка аутентифікація `/login`**
   - **Вектор:** паролі в БД зберігаються у відкритому вигляді або слабкому хеші, відсутнє rate limiting.
   - **Виявлення:** SAST, пентест-чекліст, лог-аналіз.
   - **Пом'якшення:** хешування (PBKDF2/Argon2), lockout після N спроб, 2FA (опційно).

## Виявлені ризики/знахідки (результати початкового аналізу)
- **[R1] SQLi:** Підтверджено наявність вразливості в ендпоінті `/search`. Вимагає виправлення через параметризацію запитів.
- **[R2] XSS:** Підтверджено відсутність екранування у параметрі `msg`, що дозволяє виконання довільного скрипта. Вимагає впровадження екранування HTML.
- **[R3] Weak auth:** Виявлено зберігання паролів у небезпечному форматі. Вимагає переходу на надійні алгоритми хешування.

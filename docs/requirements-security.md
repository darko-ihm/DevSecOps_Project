# Вимоги до безпеки (Фаза аналізу)

## 1. Область застосунку та модель розробки
Демонстраційний Flask-вебдодаток з аутентифікацією, пошуком та базою даних (SQLite). 
**Обрана модель розробки:** DevSecOps (інтеграція практик безпеки на всіх етапах життєвого циклу розробки).

## 2. Функціональні вимоги безпеки
- **AUTH-1:** Авторизація користувачів для доступу до сторінки профілю.
- **AUTH-2:** Блокування облікового запису після 5 невдалих спроб входу (захист від брутфорсу).
- **STOR-1:** Паролі повинні зберігатися із сіллю та стійким хешем (наприклад, Argon2 або PBKDF2).
- **LOG-1:** Аудитна подія логіну та невдалих спроб повинна фіксуватися в логах.
- **CONF-1:** Секретні ключі додатку зберігаються виключно у змінних середовища (ENV) або секретах CI/CD, а не в коді.

## 3. Нефункціональні вимоги безпеки
- **Відповідність:** Базова відповідність стандарту OWASP ASVS (рівень L1).
- **Продуктивність:** Інструменти автоматизованого тестування (DAST/SAST) не повинні критично сповільнювати час збірки проєкту.
- **Експлуатаційність:** Обов'язкова наявність процедури тріажу (сортування) та виправлення знайдених сканерами вразливостей.

## 4. Загрози (огляд)
- SQL-ін'єкції (SQLi) в параметрах пошуку.
- Міжсайтовий скриптінг (XSS) при відображенні несанітизованого користувацького вводу.
- Словникові атаки на систему аутентифікації (Weak auth) та використання небезпечних функцій хешування.
- Витік конфіденційних даних через публічний репозиторій або повідомлення про помилки.

## 5. Цілі безпеки (CIA Triad)
- **Конфіденційність (Confidentiality):** Захист персональних даних користувачів, паролів та сесій від несанкціонованого розголошення.
- **Цілісність (Integrity):** Запобігання несанкціонованій модифікації даних у базі (захист від маніпуляцій через SQLi).
- **Доступність (Availability):** Захист від базових атак типу "відмова в обслуговуванні" (DoS), забезпечення стабільної роботи сервісу під час перевірок.

## 6. Початкові ризики
Задокументовані вище вимоги та визначені загрози приймаються як базовий стан (Baseline) проєкту для подальшої інтеграції аналізаторів коду в конвеєр CI/CD згідно з обраною моделлю DevSecOps.
